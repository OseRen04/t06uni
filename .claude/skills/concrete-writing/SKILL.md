# 具体的な表現で書く (Concrete Writing)

ドキュメントを書く・編集する前に必ず確認する。目的は「読み手が追加の質問なしに、何が・どれだけ・いつ・誰によって行われたかを理解できる」文章にすること。

## 手順

1. ドキュメントの下書き・編集が終わったら、書いた文章を一文ずつ見直す。
2. 下記の「危険信号リスト」に該当する語句がないか探す。見つけたら、具体的な数値・固有名詞・条件・期限に置き換える。
3. 具体的な情報が今わからない場合は、あいまいな言葉で誤魔化さず、「未定」「TODO: ○○を計測して記入」のように欠落を明示する。あいまい語で埋めるより正直に「未確定」と書く方が良い。
4. 可能な場合は一次情報(実測値、ログ、コード、日付、担当者名)を根拠として添える。

## 危険信号リスト(見つけたら書き直す)

日本語の文書でよく紛れ込む抽象語の例:

- 程度・量: 「様々な」「多くの」「一部の」「多数の」「大幅に」「若干」
- 評価・品質: 「適切に」「効果的に」「しっかりと」「十分に」「高品質な」「使いやすい」
- 時間: 「今後」「随時」「早めに」「近日中に」「継続的に」
- 主体不明: 「関係者」「チーム」「システム側で」(誰が/何が、を明示しない)
- 結果不明: 「改善した」「向上させた」「最適化した」(何がどれだけ変わったかを書かない)

英語ドキュメントでも同様: "various", "many", "properly", "effectively", "significantly", "as needed", "the team", "improved performance" などは要注意。

## Before / After 例

- Before: 「システムのパフォーマンスを大幅に改善した」
  After: 「検索APIのレスポンスタイムを平均820ms→180msに短縮した(2026-07-10、負荷試験n=500req)」

- Before: 「多くのユーザーから好評価を得た」
  After: 「実施したアンケート(回答者32名)のうち27名が『使いやすい』と回答した」

- Before: 「今後、機能を随時追加していく予定」
  After: 「2026年8月末までにログイン機能とCSVエクスポート機能を追加予定」

- Before: 「関係者と適切に連携し、システムを効果的に運用する」
  After: 「週次ミーティング(毎週月曜10:00、開発チーム4名参加)で進捗を共有し、障害発生時は当番エンジニアが1時間以内に一次対応する」

## 例外

固有名詞化した技術用語や、意図的に不確実性を表す場合(例:「見積もりは±20%の誤差を含む」)は対象外。要件定義前の壁打ち・ブレインストーミングの初期段階では抽象語のまま進めてよいが、最終稿にする前に本チェックリストを適用する。
